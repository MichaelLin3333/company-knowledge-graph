# Implementation contract — local company knowledge graph

Root folder is this folder; keep prior atlas/study immutable. Python FastAPI backend package `backend`, entry `backend.app:app`. Bundled React/TS/Cytoscape frontend in `frontend`, built `frontend/dist` served by backend. SQLite under `data/graph.sqlite3` (env `CKG_DATA_DIR` override); atlas seed read from `seed/atlas.json` copied by root. Tests temporary databases only. Backend auto-initializes legacy seed on empty DB. Root implements `backend/quotes.py` with `QuoteService.refresh(instrument:dict, force=False)->dict` and `get_cached(instrument:dict)->dict|None`; synchronous. Root owns launchers, quote tests, integration/UI QA and packaging. No new company research or signal testing.

## IDs and objects

Use existing string IDs on seed; new stable company IDs independent of ticker. Core objects preserve unknown fields and original seed data. Arrays in JSON snapshots: companies, instruments, sources, relationships, claims, projects, participations, frontier, batches, coverage. All records have `id` canonical string; also keep original company_id / relationship_id / source_id as aliases when importing. Company fields: id,name,country,status (public/private/subsidiary/private_subsidiary/unknown),parent_id,economic_confirmation_group_id,affiliated_inference_cluster,aliases[], notes,reviewed_at. Instruments: id,company_id,ticker,exchange,currency,is_primary. Relationships: id,source_id (COMPANY ID),target_id (COMPANY ID),type,description,status,evidence_grade(primary_explicit/attributed_explicit/lead_unresolved),direction(undirected/directed),direction_review_status,scope,product,project_id,known_from,valid_from,valid_to,batch_id,claim_ids[],legacy_retention,legacy{}. Claims: id,relationship_id,subject_id,object_id,predicate,text,evidence_grade,source_ids[],locator,supporting_text,known_from,date_precision,valid_from,valid_to,terms[],supersedes_id,conflict_with_ids[],review_status. Term {value,unit,period,scope,known_from,source_ids[]}. Source: id,title,publisher,url,published_date,date_precision,retrieved_at,locator. Projects: id,name,location,status,description,source_ids[],terms[],milestones[]. Participation: id,project_id,company_id,role,source_ids[],claim_ids[]. Frontier: id,company_id|null,project_id|null,facet,status,local_depth,root_id,parent_frontier_id,reason,source_ids[],next_action,batch_id. Coverage entries may be legacy gaps or structured review slots.

## API envelopes (all JSON)

`GET /api/health` -> {status,revision,seeded,counts:{companies,relationships,sources,claims,projects,frontier},read_only_scope_note}

`GET /api/companies?q=&limit=30&offset=0` -> {items:[Company summary],total}. Company summary includes id,name,country,status,primary_ticker.

`GET /api/options` -> {relationship_types[],evidence_grades[],statuses[],countries[],products[],projects:[{id,name}],batches:[{id,name}],anchors:[{id,name}],revision,source_cutoff}. Elements other than named object arrays are strings.

`GET /api/graph?root=AAPL&depth=1&company_ids=CSV&types=CSV&evidence=CSV&statuses=CSV&country=&product=&project_id=&batch_id=&as_of=&limit_nodes=100&limit_edges=300` -> {revision,root,nodes:[Company summary],edges:[Relationship summary],hidden_nodes,hidden_edges,total_nodes,total_edges,limits:{nodes,edges},filter_note}. Server clamps <=100/300. `company_ids` is explicit visible node set for layout-safe expansion, capped; if absent BFS one-hop. Include root even if isolated. Do NOT infer transitive edges. Default accepted explicit and legacy documentary records only; excluded and unresolved-inference retained in frontier, not edges. Unresolved legacy economic direction undirected. `as_of` filters public-knowledge dates, not a claim of complete historical information; exclude unknown or too-new dates in dated view. Edge endpoints actually in returned nodes. Filters apply to relationships, countries to neighbor nodes, root retained.

`GET /api/companies/{id}` -> {company:Company,instruments:[],relationships:[],neighbors:[],projects:[],claims:[],gaps:[],frontier:[],quote:dict|null}. Company includes separate legal parent/equivalence/affiliation. `GET /api/relationships/{id}` -> {relationship,claims:[],sources:[],companies:[],project:null|dict}. `GET /api/projects` -> {items:[]}; `GET /api/projects/{id}` -> {project,participations,companies,sources,relationships}. `GET /api/research` -> {revision,frontier:[],batches:[],coverage:[],summary:{...}}. `POST /api/research/frontier` creates one manually nominated lead (no external research); validates facet and company/project, logs a revision; frontend optional queue buttons.

`POST /api/batches/validate` accepts VERSIONED BATCH OBJECT directly, returns {valid,proposal_id,batch_id,base_revision,errors:[],warnings:[],diff:{companies,relationships,claims,sources,projects,participations,frontier,superseded_claims},preview:{nodes:[],edges:[]},coverage:{...},idempotent:false}. Does not change active graph. Staged proposal is durable. `POST /api/batches/{proposal_id}/publish` body {base_revision} -> {revision,batch_id,idempotent,counts}. Atomic all-or-none; stale returns409, invalid422; same batch_id+content no-op, same ID+different content conflict.

`GET /api/revisions` -> {items:[{revision,created_at,description,snapshot_hash,batch_id}...]}. `POST /api/revisions/{revision}/restore` body {base_revision} -> {revision,restored_from,snapshot_hash}; creates new history, rejects stale. `GET /api/revisions/{revision}/diff` -> {revision,current_revision,added,removed,changed,description}. `GET /api/export?revision=N` returns JSON {schema_version,revision,snapshot,manifest}; downloaded via frontend. Quote/cache/viewstate excluded from snapshot hash.

`POST /api/instruments/{id}/refresh` body {force:false} -> quote dict from QuoteService; `GET /api/instruments/{id}/quote` cached observation only. No app-wide background quote downloads. Catch quote errors and show old snapshot with stale/error flags.

## Batch v1

{schema_version:'1.0',batch_id,name,base_revision,cutoff,mode:'company'|'project',root_company_ids:[],root_project_ids:[],max_additional_hops:2,investigated_company_ids:[],investigated_project_ids:[],companies:[],instruments:[],sources:[],relationships:[],claims:[],projects:[],participations:[],frontier:[],coverage:[],supersedes_claim_ids:[],research_log:[]}. JSON arrays default empty. Company mode <=25 distinct investigated_company_ids; project mode <=5 distinct investigated_project_ids and no deep company investigations. Enumeration companies/edges may exceed25. Hop depths checked via explicit existing+proposed adjacency from declared roots, not trusted claimed counters alone. Existing IDs not silently overwritten; use correction/supersession fields with provenance. New accepted relationship requires claim(s), resolved company endpoints, primary/attributed evidence, source URL+publisher+title, locator+supporting_text, dates precision explicit (unknown permitted), relationship predicate; no inferred/transitive evidence grade. Source dates beyond cutoff reject except planned effective dates. New claim subject/object must match relationship endpoints (either order); numerical terms require units/period/scope/known_from (unknown stays null, never inherited). Product attribution must be evidenced on claim rather than assembled from company capabilities. Project participation never generates pairwise edges. Conflicts/supersedes require existing IDs; history retained. Original record migration lossless with explicit mapping.

## Frontend behavior and price fields

Single local browser app, no remote/CDN runtime. Graph workspace with company search, root selectors existing six anchors, full filters, company/relationship drawers, synchronized paginated table, projects lens, research queue, batch validation/diff/publish, revisions diff/restore, snapshot export, help/playbook. Viewstate localStorage (positions,pins,filters,selection,bookmarks) not research DB. Native accessible buttons and inputs, drawer focus handling; desktop and mobile. Default one-hop cap100/300. Expansion add <=25 unseen neighbors and keep existing positions; graph initialization only on explicit root/filter/expand/relayout, drawer open does not rearrange. Price {instrument_id,ticker,price,currency,exchange,observed_at|null,observation_date|null,date_precision,observation_type:'provider_regular_market'|'daily_close',retrieved_at,cache_expires_at,stale,cached,error|null}; no private share quote substitution.
